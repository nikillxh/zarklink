# Zarklink Vault Daemon

Automated vault operator daemon — monitors for bridge requests and processes confirmations.

## How It Works

Each vault operator runs a daemon that:

1. **Watches** for `IssueRequested` events on the `BridgeProtocol` contract
2. **Verifies** the Zcash transaction using the relayed block headers
3. **Confirms** the deposit on Starknet to mint wZEC for the user
4. **Monitors** redemption requests and processes Zcash payouts

In devnet mode a single daemon instance handles all registered vault operators.

## Running

```bash
# Development (uses tsx)
pnpm dev

# Production
pnpm build && pnpm start

# Via orchestrator (starts with --services flag)
./scripts/start-devnet.sh --services
```

## Configuration

Loaded from `.env.devnet` (auto-generated by `start-devnet.sh`):

| Variable | Description |
|----------|-------------|
| `STARKNET_RPC_URL` | Starknet RPC endpoint |
| `ZCASH_RPC_URL` | Zcash RPC endpoint |
| `BRIDGE_PROTOCOL_CONTRACT` | BridgeProtocol contract address |
| `VAULT_POOL_CONTRACT` | VaultPool contract address |
| `VAULT_REGISTRY_CONTRACT` | VaultRegistry contract address |
| `WZEC_TOKEN_CONTRACT` | wZEC token address |
| `VAULT_PRIVATE_KEY` | Starknet private key for vault operator |
| `VAULT_DAEMON_POLL_MS` | Event polling interval (default: 3000) |

## Architecture

```
BridgeProtocol events  →  event-listener.ts  →  verifier.ts  →  confirm/redeem tx
       ↓                        ↓                    ↓
  IssueRequested          Filter & decode     Check Zcash proof
  RedeemRequested                             via relayed headers
```
